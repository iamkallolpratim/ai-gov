# Phase 3 proposal: landing site + docs

Status: **approved 2026-11-18, scaffolded** on branch `feat/site`.
Decisions D5–D7 in [ROADMAP.md](ROADMAP.md) apply.

## Why Astro + Starlight

- One project serves both a hand-designed landing page (`src/pages/index.astro`, zero JS by
  default) and a docs site (Starlight: search via Pagefind, sidebar, dark mode, i18n-ready).
- Static output → GitHub Pages with no server.
- `starlight-openapi` renders the API reference from `openapi.json`, so API docs can't
  drift from FastAPI.
- MDX lets regulation pages embed tables generated from `policies/*/MAPPING.yaml` later (ROADMAP 2.2).
- Docusaurus would also work, but it ships more JS and makes a custom marketing page more
  awkward. VitePress is weaker at OpenAPI rendering.

## Landing page sections

1. **Hero:** "Know which AI rules apply to your systems, prove you follow them, generate the evidence on demand." Demo GIF, buttons for ★ Star on GitHub / Try the live demo / Docs.
2. **Problem → solution:** four overlapping regimes tracked in stale spreadsheets → inventory + policy-as-code + evidence.
3. **Coverage grid:** EU AI Act · California ADMT · China GenAI · India DPDP. Each card shows triggers, risk tiers, rule count and a "starter / full" badge, linking to its regulation page. Counts come from `policies/` at build time, so they stay accurate.
4. **How it works:** Mermaid/SVG flow: system metadata → jurisdiction detection → risk tier → OPA/Rego → findings with article citations → evidence PDF/JSON. Includes a short Rego snippet next to the finding it produces.
5. **Architecture:** the diagram from STATE §1, simplified.
6. **Quickstart:** `git clone …` / `make demo` / open `localhost:3000`.
7. **Comparison:** table of spreadsheets vs. commercial GRC suites vs. AI Governance Console. Rows: cost, self-hosted, policy-as-code, multi-jurisdiction detection, audit trail, evidence generation, extensibility. Keep it factual and avoid naming vendors.
8. **Roadmap:** v0.2 / v0.3 highlights, linking to ROADMAP.
9. **Contribute:** "Add a jurisdiction" call-to-action, good-first-issues link, Discussions.
10. **Footer:** Apache-2.0, not-legal-advice disclaimer, GitHub, security policy.

## Build & deploy

`.github/workflows/site.yml`:

- Triggers: push to `production` touching `site/**`, `policies/**`, `app/**` (for OpenAPI), plus manual dispatch.
- Job 1: set up Python 3.12, `pip install -r requirements.txt`, then
  `ENVIRONMENT=test python -c "import json; from app.main import app; print(json.dumps(app.openapi()))" > site/openapi.json`.
- Job 2: `withastro/action` (Node 22) → `actions/deploy-pages`.
- Permissions: `pages: write`, `id-token: write`.
- **One manual step for you:** repo Settings → Pages → Source = "GitHub Actions".

## SEO / social

- `<title>`/description per page; Open Graph + Twitter card tags pointing to `og.png`.
- Sitemap generated automatically by Starlight once `site` is set; `robots.txt` references it.
- JSON-LD `SoftwareApplication` on the landing page.
- GoatCounter: one `<script data-goatcounter="https://<code>.goatcounter.com/count">`,
  gated on a `PUBLIC_GOATCOUNTER_CODE` env var so forks don't report to your account. You
  create the GoatCounter account (free).
- Custom domain later: add `public/CNAME`, set `base: "/"`.
